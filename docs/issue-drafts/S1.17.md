---
id: S1.17
title: "S1.17: Stop writing into the app's const semaphore create info"
labels: size:medium, kind:data-shape, platform:linux
---
What: The semaphore create hook writes `handleTypes` and `semaphoreType` into the app's `const` create info, and restores them only after the real create returns. An app that passes that struct from read-only memory faults, and another thread that reads the struct during the call sees altered values.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:1210-1211 (export_info->handleTypes change), packages/stearlight-runtime/vulkan_wsi_shim.c:1217 (type_info->semaphoreType change), packages/stearlight-runtime/vulkan_wsi_shim.c:1186 (const create info parameter) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 40 changed lines; C; the downgrade path needs a Vulkan loader to exercise)
Serves: M4
Done when: the hook copies the structs it changes (the export info and the type info) and passes the copies to create, so the app's struct bytes are the same after the call. A host test with the shim built against stub loader functions puts the create info in a read-only page with mprotect and calls the hook; it must succeed, and the struct must be byte-identical afterwards.
