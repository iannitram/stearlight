title: "S2.15: Make the synthetic vkWaitForPresentKHR honour present_id and timeout"
labels: size:medium, kind:wiring, platform:linux
---
What: When the host lacks VK_KHR_present_wait, the shim's vkWaitForPresentKHR logs and returns success at once, ignoring `present_id` and `timeout`. An app that paces its frames on that call gets no backpressure and its timeout is never honoured; image reuse is still guarded by the app's own acquire, so the cost is pacing.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:1031-1033 (synthetic branch returns 0), packages/stearlight-runtime/vulkan_wsi_shim.c:809-811 (synthetic_present_wait_available set) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 40 changed lines; C; the present path is only checked with a real Vulkan present on a host that lacks VK_KHR_present_wait)
Serves: M4
Done when: the synthetic branch returns success only after the present with that `present_id` completes, and returns VK_TIMEOUT when `timeout` expires first. A host test with a fake present completion and a short timeout checks both results, and a pacing app on the device shows the frame loop waiting for the present.
