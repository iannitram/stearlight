labels: size:hard, kind:wiring, platform:linux

What: With developer mode on, I accept password logins on 0.0.0.0:2222 and on tcp://:3389 with no limit per source address. The only password rule is eight characters, and each closed session admits a new connection. Developer mode is opt-in and needs a password, so this is exposure only after a person turns it on.
Where: packages/quest-runtime/linux/desktop-manager.py:250 (password rule), 267-290 (sshd_config and listener), 417-433 (accept_ssh), 326 (xrdp.ini port) (code map: docs/code-map.md#quest-linux-session)
Size: Hard (cross-cutting: sshd, xrdp and the password policy; the first decision is key-only access or a login limit, and that choice changes the setup flow)
Serves: none (cleanup)
Done when: the access decision is recorded in the pull request. Repeated failed logins from one source address are refused for a set period (the count and period are part of that decision). The password minimum matches the decision. desktop-manager tests cover both a refused address and a correct login.
