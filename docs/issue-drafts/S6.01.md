What: I want each resource import in the Venus server worker to release the descriptor it received. Today the duplicate is passed to the renderer, but the original `fds[0]` is never closed on the success or the failure path, so each import leaks one descriptor.
Where: packages/windows-runtime/windows-venus/patches/0005-share-vulkan-images-with-allocation-metadata.patch:70-78 (the `RENDER_CONTEXT_OP_IMPORT_RESOURCE` handler, `os_dupfd_cloexec(fds[0])`) (code map: docs/code-map.md#windows-runtime)
Size: Medium (about 10 changed lines in one patch file; C; needs a Windows build of the Venus renderer and a patch rebase)
Serves: none (cleanup)
Done when: a loop of 1000 imports in the Windows runtime leaves the process handle count flat, and the same loop on the Linux side leaves the descriptor count flat. The fix keeps the existing failure path, which closes the duplicate on error. The patch still applies to the pinned renderer commit in sources.lock.json.
