title: "S5.08: Open the update log with O_NOFOLLOW and O_EXCL"
labels: size:medium, kind:state, platform:linux
---
What: I want the update UI to open its log only as a file it has just created, so a symlink planted at the fixed /tmp name cannot make it truncate and write another file. The default path is /tmp/quest-native-updater.log, and it is opened with O_CREAT and O_TRUNC but without O_NOFOLLOW or O_EXCL. On kernels with protected_symlinks enabled this is mitigated, but the code should not rely on that setting.
Where: packages/quest-runtime/linux/steam-update-ui.cpp:65 (the `open` of QUEST_UPDATE_LOG) and :24 (the default path) (code map: docs/code-map.md#quest-linux-bridges)
Size: Medium (about 15 changed lines; C++; platform linux)
Serves: none (cleanup)
Done when: the log is removed if it exists and is then opened with O_CREAT|O_EXCL|O_NOFOLLOW. If the path is a symlink or another user's file, the open fails and the updater runs without a log, as it already does when open() fails. Checked on the Linux build host: build the shim with QUEST_UPDATE_LOG pointing at a scratch path, plant a symlink there to a scratch file, run the update UI path, and confirm the scratch file's contents and size are unchanged.
