What: I want the `steam` session to start a Steam client that the image contains. The default `CLIENTCMD` runs `/usr/local/libexec/stearlight/launch-steam`. No file in the repo creates that path, and the Containerfile does not install it, so the session exits 127 at the `wait` in the session script. The `steamframe` session sets its own `CLIENTCMD`, so the VM path is not affected.
Where: system_files/usr/share/gamescope-session-plus/gamescope-session-plus:61, :229; system_files/usr/share/gamescope-session-plus/sessions.d/steam:59; system_files/usr/share/wayland-sessions/gamescope-session-steam.desktop:4; Containerfile:132-137 (code map: docs/code-map.md#system-files)
Size: Medium (about 40 changed lines across the session files and the Containerfile; bash and Dockerfile; checked by an image build and a device session)
Serves: M1
Done when: either the image installs a `launch-steam` at that path, or the default `CLIENTCMD` in both session files names a binary the Containerfile really installs. The `steamframe` session is unchanged. On a device, the `steam` session starts the client and its log has no exit 127.
