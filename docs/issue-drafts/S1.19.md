---
id: S1.19
title: "S1.19: Keep the registered HMD alive when a later registration fails"
labels: size:medium, kind:state, platform:linux
---
What: If the left or right controller registration fails after the HMD was already added to SteamVR, the failure branch resets `hmd_` and frees the HMD object that SteamVR still holds a pointer to. A later call from SteamVR into that pointer is a use-after-free; the actual risk depends on whether the host calls into the driver after a failed Init.
Where: packages/stearlight-runtime/fake_tracking.cpp:632-639 (registration failure branch), packages/stearlight-runtime/fake_tracking.cpp:637 (hmd_.reset()) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 15 changed lines; C++ against the OpenVR driver headers; the failure needs a host that rejects a registration)
Serves: M4
Done when: after a failed Init the HMD object stays alive until Cleanup, and the controllers are still released in the failure branch. A host test with a fake server host that fails the second TrackedDeviceAdded calls the HMD pointer it registered after Init returns, and runs clean under AddressSanitizer.
