title: "S2.20: Cache the driver vkQueueSubmit pointer per device"
labels: size:medium, kind:wiring, platform:linux
---
What: vkQueueSubmit resolves the driver's function pointer on every call, which runs a device proc lookup and string compares each time. That is extra work on the hottest path in the shim, once per submit.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:1320-1322 (lookup in vkQueueSubmit), packages/stearlight-runtime/vulkan_wsi_shim.c:1100-1110 (resolve_real_queue_proc) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 15 changed lines; C; the per-submit cost is only measurable on a device)
Serves: M4
Done when: the resolved pointer is cached after the first successful lookup, keyed by device, and a NULL result is never cached. A host test with a stubbed device proc lookup counts lookups across 1000 submits and gets 1 for one device.
