title: "S2.16: Retry the timeline backing signal instead of stopping the worker"
labels: size:medium, kind:state, platform:linux
---
What: The timeline bridge worker reads the GPU counter, then signals a value computed from that read. If the counter moves past that value before the signal, the driver rejects the signal as non-increasing, and the worker exits on "backing signal failed" with nothing to restart it, so that timeline stops advancing for the rest of the run.
Where: packages/stearlight-runtime/vulkan_timeline_bridge.inc:65 (counter read), packages/stearlight-runtime/vulkan_timeline_bridge.inc:74-78 (signal and break) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 30 changed lines; C; the race needs a driver that rejects non-increasing signals to reproduce)
Serves: M4
Done when: a signal rejected because the counter moved on re-reads the counter and signals again, and the worker only exits on stop or a counter query failure. A host test with the worker built against a fake counter and signal, where the counter advances between read and signal, checks that the worker keeps signalling.
