title: "S2.05: Stop the Mesa shared-timeline submit from blocking on the KGSL fence"
labels: size:hard, kind:state, platform:linux
---
What: I want a Mesa submit that signals a shared timeline to return without waiting for the KGSL completion fence, so the CPU and the GPU stop running one job at a time and a hung GPU cannot block the calling thread forever. In Mesa's immediate mode this runs on the application thread, so the block reaches vkQueueSubmit.
Where: packages/quest-runtime/linux/mesa-shared-timeline.h:188 (`quest_kgsl_queue_submit`, the `kgsl_syncobj_wait` call with `UINT64_MAX`) (code map: docs/code-map.md#quest-linux-bridges)
Size: Hard (about 120 changed lines; C with Mesa internals; platform linux; needs a Quest 2 (Snapdragon XR2 Gen 1, Adreno 650) to check; the completion path is an open design question)
Serves: M4
Done when: a shared-signal submit no longer waits on `completion.syncobj` inside the submit call. The timeline value is signaled from the completion path, or the wait is bounded and returns VK_ERROR_DEVICE_LOST on timeout. Checked on a Quest 2: a submit that signals a shared timeline returns before its GPU job finishes, and a deliberately stalled job no longer blocks the submitting thread indefinitely.
