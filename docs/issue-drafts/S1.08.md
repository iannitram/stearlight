title: "S1.08: Reject out-of-range image indices in vkQueuePresentKHR"
labels: size:medium, kind:state, platform:linux
---
What: I want vkQueuePresentKHR to refuse an image index at or above QUEST_GPU_BUFFERS, instead of writing and reading past the end of the per-slot arrays. An application that passes such an index today makes the present path write `presentIds[slot]` and read `acquired[slot]` out of bounds, inside the app's own process.
Where: packages/quest-runtime/linux/quest_wsi.cpp:330 (`slot` read from `pImageIndices[i]`) and the uses of `slot` below it in vkQueuePresentKHR (code map: docs/code-map.md#quest-linux-bridges)
Size: Medium (about 10 changed lines; C++ Vulkan layer; platform linux; the present path only runs against a real Vulkan present)
Serves: M4
Done when: for an index at or above QUEST_GPU_BUFFERS, the call returns VK_ERROR_UNKNOWN for that swapchain (and sets pResults[i] when pResults is set) and writes nothing to presentIds, released, acquired or the frame counter. Valid indices behave as before. Checked on a Quest 2 with the Vulkan validation layer enabled: an out-of-range present reports an error, and normal presents show no change in frame rate.
