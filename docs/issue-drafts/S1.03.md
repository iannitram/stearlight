title: "S1.03: Wait for and kill desktop app processes when the desktop bridge closes"
labels: size:medium, kind:state
---
What: I want closing the desktop bridge to end its app processes for sure. close() sends TERM with destroy() and never waits, and the comment in QuestActivity says PRoot can ignore TERM, so a desktop app can outlive the session.
Where: packages/quest-runtime/app/src/main/java/net/stearlight/quest/DesktopAppBridge.java:106-110; PRoot launch arguments at :54 (code map: docs/code-map.md#quest-app-java)
Size: Medium (about 25 changed lines; Java for Android, checked on a Quest 2)
Serves: M1
Done when: close() waits a bounded time for each desktop app process after the stop signal and kills any that remain, so none is alive when close() returns. Checked on a Quest 2 by starting a desktop app, leaving Desktop mode, and listing the processes in the rootfs: no app process remains.
