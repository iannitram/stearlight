title: "S5.13: Escape control bytes in names written to the shim log"
labels: size:medium, kind:pure-fn, platform:linux
---
What: vkGetInstanceProcAddr writes the app-supplied function name verbatim into the shim log and the serial console. A name with a newline or an escape byte can forge a log line or change what a terminal shows when someone reads the serial output. Only the app that supplies the name can do this, and that app already runs in-process, so the impact is low.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:2559-2563 (gipa log line, snprintf at :2562), packages/stearlight-runtime/vulkan_wsi_shim.c:618-632 (shim_log writes to both files) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 15 changed lines; C; the helper lives in the shim, so the host check needs the shim built with loader stubs)
Serves: none (cleanup)
Done when: control bytes (below 0x20 and 0x7f) in the name are replaced before logging, and the 160-byte message limit still holds. A host test passes a name with a newline and an escape byte and checks that the logged line has neither.
