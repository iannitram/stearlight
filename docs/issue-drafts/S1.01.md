title: "S1.01: Bound the Linux session stop so a missing pid cannot hold the session lock"
labels: size:medium, kind:state
---
What: I want the Linux session stop to finish in bounded time. When linux.pid is missing or unreadable, the fallback can leave the process running, and stopLinux then waits with no limit while startLinux still holds linux-session.lock.
Where: packages/quest-runtime/app/src/main/java/net/stearlight/quest/QuestActivity.java:111-132 (stopLinux, killLinux); lock taken at :104-108 (code map: docs/code-map.md#quest-app-java)
Size: Medium (about 40 changed lines; Java for Android, checked on a Quest 2)
Serves: M1
Done when: stopLinux returns within about 10 seconds even if the Linux process ignores TERM, logs an error that names the pid lookup failure, and releases linux-session.lock. Checked on a Quest 2 by stopping the activity while linux.pid is removed, then starting the app again: the new session gets the lock within 15 seconds.
