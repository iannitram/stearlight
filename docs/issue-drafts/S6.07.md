title: "S6.07: fix the missed wakeup on idle Windows rings instead of polling"
labels: size:hard, kind:state, platform:windows, after-1.0
---
What: I want the idle Windows ring to wake on a real notification, not a bounded 1 ms poll. The patch re-checks the queue every 1 ms to cover a wakeup the guest can miss while it publishes a command. The poll works, but the cost is wakes on every idle ring. The wake rate is smaller than the first estimate: the 1 ms timeout gives about 1000 wakes per second only when the timer resolution is raised, and the default Windows granularity (about 15.6 ms) gives about 64 wakes per second per ring.
Where: packages/windows-runtime/windows-venus/patches/0006-recheck-pending-commands-in-idle-windows-rings.patch (the `SleepConditionVariableCS(..., 1)` loop in `vkr_ring.c`) (code map: docs/code-map.md#windows-runtime)
Size: Hard (about 40 changed lines; C; the cause of the missed notify is an unknown on the publishing side of the ring)
Serves: none (cleanup)
Done when: I have measured wakes per second on an idle ring before and after, on the Windows build host. A test that publishes one command to an idle ring completes without relying on the 1 ms timeout. The root cause of the missed notify is written up in the PR.
