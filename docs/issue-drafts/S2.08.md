What: I want the SDL gamepad adapter to remember that the shared state file is missing and retry the open at a fixed interval. With no physical pad and no state file, each SDL_PollEvent and SDL_PumpEvents call currently repeats the failing open() on the game's frame loop.
Where: packages/quest-runtime/linux/sdl-gamepad.cpp:68 (`open` in `map()`, reached from `feed()`) (code map: docs/code-map.md#quest-linux-bridges)
Size: Medium (about 30 changed lines; C++ with SDL2; platform linux)
Serves: M4
Done when: with no pad and no state file, open() on the state path runs at most once per retry interval (one second is a suggested value). When the file appears, its mapping is picked up within one interval. Checked on the Linux build host by running an SDL program that polls events in a loop under strace: one open() per interval, not one per poll. Then creating the state file makes input arrive within one interval.
