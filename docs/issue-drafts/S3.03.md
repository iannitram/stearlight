What: I refresh a game's FEX rootfs only when the Steam platform manifest changes. An APK update that replaces the libraries in the FEX runtime leaves the old copies in place, because the stamp does not cover them.
Where: packages/quest-runtime/linux/fex-game-launcher.py:37-38 (the stamp) and 85-95 (library copies from /opt/quest/fex-runtime) (code map: docs/code-map.md#quest-linux-session)
Size: Medium (about 15 changed lines; Python; the FEX runtime path is hard-coded, so a host test needs it passed in as a parameter)
Serves: M3
Done when: a change to a file under /opt/quest/fex-runtime changes the stamp, and the next launch replaces the copied library. A test with a temporary runtime tree shows that an unchanged tree keeps the stamp and skips the copy.
