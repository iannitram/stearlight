title: "S4.27: ANGLE visual probe finds dlsym on current glibc"
labels: size:medium, kind:wiring
---
What: I want the ANGLE visual probe to resolve the real `dlsym` without assuming a glibc symbol version the build host does not export. On an x86_64 build host, `dlvsym(RTLD_NEXT, "dlsym", "GLIBC_2.17")` returns NULL, and the next line calls that NULL pointer, so the probe crashes before the EGL contract check runs.
Where: tests/angle-visual-test.c:51-52 (the version lookup and its first call); packages/stearlight-runtime/angle_visual_interposer.c:27 uses the same version string for the ARM64 guest and should be checked with the same change (code map: docs/code-map.md#tests)
Size: Medium (about 10 changed lines; C; needs the ANGLE EGL library and an X display to reach the contract check, so it cannot be checked on the host alone)
Serves: none (cleanup)
Done when: on an x86_64 build host with ANGLE present, the probe reaches the `EGL CONTRACT PASS` line or a named failure message, and never dereferences NULL. The lookup tries `GLIBC_2.34`, then `GLIBC_2.2.5`, and if neither resolves the probe prints a message and returns nonzero. The ARM64 guest build of the interposer still resolves its symbol under the change.
