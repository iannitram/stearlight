What: I want the arm64 capture helper to put the QEMU window back to normal z-order and restore the cursor even when the capture throws. Today `SetWindowPos` sets `HWND_TOPMOST` and nothing reverts it. The cursor restore is skipped if the capture throws after the cursor moves. With `-KeepRunning`, the script exits and leaves the QEMU window topmost, because the outer `finally` stops the process only when `-KeepRunning` is not set.
Where: tests/test-arm64.ps1:474-509 (the `Capture` method: `SetWindowPos` at :476, the cursor move at :491, the restore at :508) (code map: docs/code-map.md#tests)
Size: Medium (about 12 changed lines; PowerShell with inline C#; Windows host)
Serves: none (cleanup)
Done when: after `Capture` returns or throws, the window is not topmost (a `HWND_NOTOPMOST` call sits in a `finally`), and the cursor position is restored. A run with `-KeepRunning` leaves the window at normal z-order. The check is run on the Windows host with a capture that is forced to throw.
