What: I want the emulated epoll_wait to look up the registration for each returned event without copying the whole registration map. Today every call that returns events copies the map under epollsLock and then scans events against registrations on the player's hot loop.
Where: packages/quest-runtime/linux/video-bridge.cpp:279 (the map copy) and :280 (the events-by-registrations scan) (code map: docs/code-map.md#quest-linux-bridges)
Size: Medium (about 30 changed lines; C++; platform linux)
Serves: M4
Done when: epoll_wait holds epollsLock only while it looks up the registrations it needs, and not for the whole scan. The reported events are the same as before: EPOLLIN for a registered fd on the same epoll instance, with EPOLLERR and EPOLLHUP added. Checked on a Quest 2 with the streaming player: frame delivery is unchanged and the main thread's CPU time drops.
