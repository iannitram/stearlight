What: I want a recovery download killed mid-way (power loss, SIGKILL) to stop blocking every later run, instead of requiring someone to delete the `.partial` file by hand.
Where: build_files/fetch-recovery.py:43-44 (exclusive open of the `.partial` file, then `created = True`), build_files/fetch-recovery.py:65-67 (cleanup branch); tests/recovery-test.py:41-47 (asserts the current FileExistsError) (code map: docs/code-map.md#build-and-ci)
Size: Medium (about 15 changed lines; Python; the behaviour change conflicts with a deliberate test assertion, so it needs a decision)
Blocked by: delete this line
Serves: none (cleanup)
Done when: a rerun after a killed download either completes, or fails with a message that names the leftover `.partial` path and says to delete it; the choice is recorded in the PR description. The existing assertion in tests/recovery-test.py that expects `FileExistsError` is updated to match the chosen behaviour, and `bash build_files/check.sh` passes.

Note for whoever picks this up: the current test says a leftover partial must not be overwritten, which reads as a guard against two runs writing the same file. Removing a partial file automatically is only safe if no other run holds it, so the decision is about that guard, not only the cleanup.
