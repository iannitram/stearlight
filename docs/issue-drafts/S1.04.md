What: I want a frame that fails validation to send a response with no payload. The response status is set to -1 but its byte count stays set, so the frame bytes follow a failure reply that the Linux client does not read, which can desynchronize the connection.
Where: packages/quest-runtime/app/src/main/cpp/video_bridge.cpp:145-148 (client check at packages/quest-runtime/linux/video-bridge.cpp:69) (code map: docs/code-map.md#quest-app-native)
Size: Medium (about 15 changed lines; C++ for Android, checked on a Quest 2)
Serves: M4
Done when: a frame that fails validation sends a response with status -1 and bytes 0, and no payload follows it on the socket. Checked on a Quest 2 with a stream that sends one invalid frame and then valid frames: the Linux client keeps decoding after the failure.
