title: "S2.18: Block waiters on the aliased queue lock instead of spinning"
labels: size:medium, kind:state, platform:linux
---
What: The aliased-queue lock is held across vkQueuePresentKHR, vkQueueWaitIdle and vkDeviceWaitIdle, and every other caller spins on it with sched_yield. A long GPU wait in one thread makes each other submit on that queue burn CPU for the whole wait.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:1060-1071 (present under the lock), packages/stearlight-runtime/vulkan_wsi_shim.c:1083-1088 (spin loop), packages/stearlight-runtime/vulkan_wsi_shim.c:1377-1379 (vkQueueWaitIdle), packages/stearlight-runtime/vulkan_wsi_shim.c:1388-1390 (vkDeviceWaitIdle) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 40 changed lines; C; contention only shows on a device with the aliased queue in use)
Serves: M4
Done when: waiters block (a mutex and condition variable) instead of spinning on sched_yield. Whether the wait calls still need the lock is part of the same change, and I record the answer in the PR. On the device, a second thread submitting while another thread waits idle shows near-zero CPU use in the blocked thread.
