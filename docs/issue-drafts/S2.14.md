title: "S2.14: Stream the SteamOS update bundle to disk instead of holding it in memory"
labels: size:medium, kind:data-shape, platform:linux
---
What: I hold a whole SteamOS update bundle in memory, then copy it twice to split off the signature. On a headset with little free RAM this can end in MemoryError, which the top-level handler does not catch, so no failure is written to progress.json.
Where: packages/quest-runtime/linux/steam-os-update.py:119-129 (verified_bundle; the fetch at line 65 reads the whole response) (code map: docs/code-map.md#steam-update)
Size: Medium (about 40 changed lines; Python; the bundle size is not in the repo, so the gain is not measured yet)
Serves: M4
Done when: the bundle is written to CACHE in chunks and the signature is read by seeking, so peak Python memory no longer grows with the bundle size. A test with a generated 64 MiB bundle, run under tracemalloc, keeps the peak under 16 MiB. verified_bundle still rejects a bad signature length and a truncated bundle.
