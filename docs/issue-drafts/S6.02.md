labels: size:medium, kind:data-shape, platform:windows, after-1.0

What: I want a defined result for `mmap` on a Windows `fildes` that is a raw HANDLE rather than a token or a CRT descriptor. The patch removes the old raw-HANDLE fallback, so such a call now returns `MAP_FAILED` with `EBADF`, while the token guard at `0x40000000` keeps stale tokens away from `_get_osfhandle`.
Where: packages/windows-runtime/windows-venus/patches/0001-resolve-windows-handle-tokens-before-crt.patch (the `os_get_win32_handle_from_fd` hunk and the `mman_win32.c` hunk that replaces the fallback with `return MAP_FAILED;`) (code map: docs/code-map.md#windows-runtime)
Size: Medium (about 40 changed lines in one patch file; C; Windows UCRT build)
Serves: none (cleanup)
Done when: I have listed each caller that sends a raw HANDLE through the Venus proxy, and the PR says either that none remain (the call fails with `EBADF`, and a test shows it) or that the fallback is kept for them. A Windows build of the runtime passes its existing smoke test with both outcomes covered.
