title: "S5.17: Stop root writing fixed names in /tmp at boot"
labels: size:medium, kind:wiring, platform:linux
---
What: I want the boot script to stop writing fixed file names directly under `/tmp` as root. It writes `/tmp/stearlight-xorg.conf` with a heredoc at line 224, and it also writes the Xorg log and the audio log in `/tmp`. `/tmp` is world-writable, so a symlink left there by the session user could redirect a root write to any file. The risk needs a link that survives a reboot, so this is hardening, not an active exploit. I would move these files into a root-owned directory such as `/run/stearlight`, or create them with noclobber.
Where: system_files/etc/local.d/arm64-vm.start:224, :253, :281, :353 (code map: docs/code-map.md#system-files)
Size: Medium (about 15 changed lines; POSIX sh; checked by a VM boot)
Serves: none (cleanup)
Done when: no root-run redirect in the boot script writes a fixed name directly under `/tmp`. The X server still starts, and the audio check still prints its READY line. Checked by a VM boot.
