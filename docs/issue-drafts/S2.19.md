title: "S2.19: Remove the per-frame X round trip from the Mesa PutImage patch"
labels: size:medium, kind:wiring, platform:linux
---
What: The Mesa X11 patch adds a synchronous `xcb_get_input_focus` round trip after every successful PutImage, so each software-presented frame waits for an X server reply before the present thread continues. The reply is used only as a completion boundary, and the cost is paid on every frame.
Where: packages/stearlight-runtime/mesa/0001-complete-x11-software-presents.patch:8-27 (added block), packages/stearlight-runtime/mesa/0001-complete-x11-software-presents.patch:13 (the synchronous call) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 30 changed lines in the patch; C in the Mesa tree; needs a Mesa build and an X server)
Serves: M4
Done when: the synchronous round trip is removed or runs once per batch of presents, and a present id is still published only after the X server has processed its PutImage. I check that on the build host with the Mesa X11 software present path against an Xvfb server, including the present id ordering.
