title: "S5.22: Turn X access control back on in the VM boot script"
labels: size:medium, kind:wiring, platform:linux
---
What: I want the Xorg server started by the boot script to keep X access control on. It runs with `-ac`, which disables that control, so any local process can connect to display `:0` without a cookie, capture the screen or inject input. The socket directory `/tmp/.X11-unix` is world-writable by design, so the cookie is the only gate that matters.
Where: system_files/etc/local.d/arm64-vm.start:215, :252 (code map: docs/code-map.md#system-files)
Size: Medium (about 15 changed lines; POSIX sh and xauth; the Steam and gamescope clients must authenticate, so checked by a VM boot)
Serves: none (cleanup)
Done when: Xorg starts without `-ac`. A client running as the stearlight user connects with the generated cookie. A process without the cookie is refused. Checked by a VM boot, with a `xset q` from a process that has no cookie failing.
