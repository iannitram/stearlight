---
id: S5.14
title: "S5.14: Reject timeline fds that are not sealed against shrinking"
labels: size:medium, kind:data-shape, platform:linux
---
What: The timeline bridge import checks the fd's size and maps it, but never checks the fd's seals. The exporter seals its fds, so this matters only for an unsealed fd from the importing app; such a holder can truncate the fd after the size check, and the next worker access to the mapping raises SIGBUS.
Where: packages/stearlight-runtime/vulkan_timeline_bridge.inc:185-189 (timeline_import size check and mmap), packages/stearlight-runtime/vulkan_timeline_bridge.inc:169 (exporter seals) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 15 changed lines; C; the bridge is experimental and off by default, so the host check needs the shim built with loader stubs)
Serves: none (cleanup)
Done when: the import reads the seal set with F_GET_SEALS and rejects an fd without F_SEAL_SHRINK, returning the same error code as the size check. A host test passes an unsealed memfd and gets the rejection, and a memfd sealed with F_SEAL_SHRINK is accepted.
