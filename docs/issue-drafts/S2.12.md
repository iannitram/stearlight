What: I want the Bluetooth bridge to skip parsing bluetooth-devices.tsv when its text matches the previous pass. Today `synchronize()` runs on every loop iteration, so the file is read, parsed and rebuilt into a new map about ten times a second even when nothing changed.
Where: packages/quest-runtime/linux/bluetooth-bridge.cpp:288 (read and parse at the top of `synchronize`) and :555 (its call in the bus loop) (code map: docs/code-map.md#quest-linux-bridges)
Size: Medium (about 15 changed lines; C++ with libdbus; platform linux)
Serves: M4
Done when: when the file text equals the text from the previous pass, `synchronize` returns before parsing. A change in the file is applied on the next pass. Checked on a Quest 2: after the first pass, a minute of idle time logs zero parses. On the Linux build host, a libdbus test writes the file, runs two passes and checks that the second pass changes nothing.
