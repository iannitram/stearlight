labels: size:medium, kind:state, platform:linux

What: I want the swapchain setup to close the DMA-BUF file descriptors it received over the GPU socket when it returns early. Today repeated failed vkCreateSwapchainKHR calls leak up to three fds each until the process hits EMFILE.
Where: packages/quest-runtime/linux/quest_wsi.cpp:262 (`initialize` of the swapchain: the `recvmsg` call and the returns after it) (code map: docs/code-map.md#quest-linux-bridges)
Size: Medium (about 25 changed lines; C++; platform linux)
Serves: M4
Done when: every return after `recvmsg` that does not hand an fd to Vulkan closes the descriptors received with the message. That covers the hello check, the control-message check, the framePool check, the image import checks, and a failed vkAllocateMemory. A successful import still gives each fd to Vulkan and sets its entry in `fds[]` to -1. Checked on a Quest 2 by calling vkCreateSwapchainKHR in a loop with a bad hello, and reading the entry count of /proc/self/fd; the count stays flat.
