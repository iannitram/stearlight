title: "S1.16: Keep the Vulkan 1.2 timeline bit at its real offset"
labels: size:medium, kind:data-shape, platform:linux
---
What: With the timeline bridge off, the shim's feature mask zeroes the wrong field. The shim puts `timelineSemaphore` at byte offset 108, which is `descriptorBindingStorageBufferUpdateAfterBind` in `VkPhysicalDeviceVulkan12Features`, so that feature is turned off while the real timeline bit (offset 164) stays on.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:278 (VkVulkan12FeaturesCompat padding), packages/stearlight-runtime/vulkan_wsi_shim.c:976 (mask_timeline_semaphore_features) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 10 changed lines; C; the result is only visible through a real Vulkan device, plus a layout check against the Vulkan headers)
Serves: M4
Done when: the padding before `timelineSemaphore` holds 37 entries, so the field sits at offset 164. A host check built against the Vulkan headers asserts `offsetof(VkVulkan12FeaturesCompat, timelineSemaphore) == offsetof(VkPhysicalDeviceVulkan12Features, timelineSemaphore)`, and on a device with the bridge off the feature query reports `timelineSemaphore` false and `descriptorBindingStorageBufferUpdateAfterBind` true.
