title: "S1.18: Set sType and pNext on the appended queue family element"
labels: size:medium, kind:data-shape, platform:linux
---
What: When the shim appends its compute alias to the queue family list, it fills `queueFamilyProperties` and `queueFlags` of the last `VkQueueFamilyProperties2` element, but leaves that element's `sType` and `pNext` as the app had them. An app that reuses the array with stale values there hands the loader an element with a wrong `sType` or a stray `pNext`, which a validation layer can report.
Where: packages/stearlight-runtime/vulkan_wsi_shim.c:1557-1559 (appended element in vkGetPhysicalDeviceQueueFamilyProperties2) (code map: docs/code-map.md#stearlight-runtime)
Size: Medium (about 5 changed lines; C; the loader ignores this `sType` on this path, so the check is a validation layer run on a real device)
Serves: M4
Done when: the appended element has `sType` set to 1000059001 (VK_STRUCTURE_TYPE_QUEUE_FAMILY_PROPERTIES_2) and `pNext` set to NULL. A host test with a stub real query asserts both fields after the call, and a run with the Khronos validation layer reports nothing about that element.
